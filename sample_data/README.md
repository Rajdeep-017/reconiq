# ReconIQ sample data

Synthetic e-commerce reconciliation data used by the backend tests, the demo
seed, and local development. All values are generated by `generate_data.py`
with a fixed random seed; no customer data is included.

## Layout

- `data/` - generated CSV fixtures
- `generate_data.py` - seeded generator (`random.seed(42)`)

## Regenerate

```bash
cd sample_data
python generate_data.py
```

The generator overwrites every CSV in `data/`.

## Files

- `orders.csv` - 203 orders, including three brief rows
- `settlements.csv` - 187 settlement records with intentional discrepancies
- `cod_remittances.csv` - 50 COD remittance records
- `freight_invoices.csv` - 184 freight invoice records
- `returns.csv` - 29 return records
- `warehouse_scans.csv` - 174 warehouse scan events
- `ground_truth.csv` - expected reconciliation status per order
- `zone_master.csv` - zone-to-pincode mapping
- `rate_card_*.csv` - per-zone, per-weight-slab rate cards

## Intentional discrepancies

| Discrepancy | How it is represented |
|---|---|
| Short payment | Settlement net < order net |
| Rs 10 boundary | Short payment of exactly 10.00 |
| Missing settlement | Order has no matching settlement |
| Duplicate settlement | Same order settled twice |
| Partial COD remittance | Remitted < COD collected |
| Pending COD remittance | Remitted = 0, status Pending |
| Freight overcharge | Charged weight > actual weight |
| TCS/TDS | Deducted in settlement, excluded from leakage |
| Refund mismatch | Refund amount < order net |

## Ground truth

`data/ground_truth.csv` lists every order with its expected
`status_before_review` value:

- `reconciled`
- `missing_settlement`
- `missing_cod_remittance`
- `missing_freight_invoice`
- `no_settlement_expected`
