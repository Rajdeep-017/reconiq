# Sample Data — ReconIQ

Synthetic e-commerce reconciliation dataset for development, testing, and
demonstration of the ReconIQ reconciliation engine.

## Directory layout

```
reconiq_sample_data/
├── README.md              # this file
├── generate_data.py       # data generator (re-run to regenerate all CSVs)
└── data/                  # generated CSV files
    ├── orders.csv                         # 203 orders (incl. 3 brief rows)
    ├── settlements.csv                    # 187 settlement records (with discrepancies)
    ├── cod_remittances.csv                # 50 COD remittance records
    ├── freight_invoices.csv               # 184 freight invoice records
    ├── returns.csv                        # 29 return records
    ├── warehouse_scans.csv                # 174 warehouse scan events
    ├── ground_truth.csv                   # expected reconciliation status per order
    ├── zone_master.csv                    # zone-to-pincode mapping
    ├── rate_card_marketplace_1.csv        # per-zone rate card
    ├── rate_card_marketplace_2.csv
    ├── rate_card_marketplace_3.csv
    ├── rate_card_quick_commerce_1.csv
    ├── rate_card_quick_commerce_2.csv
    ├── rate_card_website.csv
    ├── rate_card_courier_a.csv
    └── rate_card_courier_b.csv
```

## Data sources

All files are synthetic, generated by `generate_data.py` (`random.seed(42)`).
Re-run the generator to regenerate:

```bash
python generate_data.py
```

## Intentional discrepancies (for testing reconciliation)

| Discrepancy | How it's represented |
|---|---|
| Short payment | Settlement net < order net amount |
| Rs 10 boundary | Short payment of exactly ₹10.00 |
| Missing settlement | Order has no matching settlement record |
| Duplicate settlement | Same order settled twice |
| Partial COD remittance | Remitted < COD collected |
| Pending COD remittance | Remitted = 0, status "Pending" |
| Freight overcharge | Charged weight > actual weight |
| TCS/TDS | Deducted in settlement, excluded from leakage |
| Refund mismatch | Refund amount < order net |

## Brief rows (specified in requirements)

| Order Reference | Partner | Notes |
|---|---|---|
| ORD-W-204118 | Website | Delivered, Prepaid |
| ORD-M-88120 | Marketplace 1 | Delivered, COD |
| ORD-W-204377 | Website | Delivered, COD |

These three orders appear in `orders.csv`, `settlements.csv`, `cod_remittances.csv`
(where applicable), `freight_invoices.csv`, and `ground_truth.csv`.

## Ground truth

`data/ground_truth.csv` lists every order with its expected
`status_before_review` value:
- `reconciled` — settlement, COD (if applicable), and freight all present
- `missing_settlement` — no settlement record for the order
- `missing_cod_remittance` — COD order with no remittance
- `missing_freight_invoice` — no freight invoice for the order
- `no_settlement_expected` — cancelled order

## Rate cards

`data/rate_card_<partner>.csv` files contain per-zone, per-weight-slab
shipping rates with effective date ranges. Used by the reconciliation engine
to compute expected freight charges.

## Copy into repo

To make these files available to the application, copy `data/` into
`/sample_data` at the repo root:

```bash
cp reconiq_sample_data/data/* sample_data/
```
